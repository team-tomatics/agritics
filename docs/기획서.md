### 경매 시각과 보고서 시각

가락시장은 품목마다 경매 시각이 다르다. 그날 가격은 경매가 끝나야 확정되므로 보고서는 **경매 시각 기준**으로 만든다. 토마토는 02:00 경매 → 경락가 확정 · 데이터 반영(4시간) → **06:00 보고서** → 점주 · 본사가 아침 구매 전에 읽고 "오늘 더 살지, 하루 미룰지" 판단한다.

| 품목 분류 (가락시장 경매 시간표) | 경매 시각 | 보고서 시각 (경매 + 4시간) | 이번 구현 |
|---|---|---|---|
| 과일류 — 토마토 · 방울토마토 · 딸기 · 포도 · 참외 등 | 02:00 | 06:00 | 토마토 |
| 과일류 — 사과 · 배 · 수입과일 등 | 08:00 | 12:00 | 설계 |
| 채소류 — 상추 · 시금치 등 규격 출하품 | 18:30 | 22:30 | 설계 |
| 채소류 — 배추 · 양파 | 23:00 | 다음날 03:00 | 설계 |

→ 품목을 늘리면 품목별 경매 시각으로 보고서 시각이 정해진다 (설정값 `auction_time`).

## ① 이해관계자 가치 (Pain Point)

주 사용자: 외식 프랜차이즈 — 실습가이드 예시 "프랜차이즈 수요 예측"(점주 · 본사 SCM · 경영진)과 같은 구조다.

| 이해관계자 | 지금 겪는 불편 (근거) | 우리가 주는 가치 |
|---|---|---|
| 가맹점주 (주 사용자) | 본사가 채소는 점주가 직접 사게 해서 가격 변동을 점주가 떠안는다. 토마토를 적게 넣으면 배달앱 리뷰로 불만이 바로 돌아온다 (아시아타임즈 2024.9) | 매일 아침 "오늘 더 살지, 하루 미룰지" 판단에 쓰는 내일 가격 + 읽기 쉬운 일일 보고서 |
| 본사 구매 · SCM | 연간 계약을 해도 수급 비상 때는 물량이 모자란다. 2020년 장마 · 태풍으로 도매가가 2배를 넘자 롯데리아 · 버거킹이 토마토를 뺐다 (이투데이 2020.9). 2025년에는 계약 단가를 약 30% 올렸다 (아시아경제 2025.4) | 급등 조짐을 먼저 보고 보충 구매 또는 "토마토 제외" 공지를 미리 결정 |
| 경영진 · 메뉴팀 | 토마토를 줄이거나 빼면서 품질 · 브랜드가 손상된다 (아시아경제 2025.4) | 대체 메뉴 결정을 하루라도 앞당김 |
| 확장: 농협 · 산지 / 정부 | 출하 시점을 정해야 하는 산지, 수급 안정 정책을 펴야 하는 정부도 같은 "내일 가격"이 필요하다 (교수님 피드백) | 같은 API · 보고서를 출하 · 수급 판단용으로 — 발표에서 확장 방향으로 제시 |

### 경영진 관점 가치 — 얼마나 줄일 수 있나

토마토 3년치(2023.10–2026.09 · 908거래일) 가락시장 경락가로 계산했다.

| 무엇 | 값 | 뜻 |
|---|---|---|
| 하루 가격 변동 | 평균 8.4% (전날 대비 변동률의 절댓값 평균) | 매일 "오늘 살지, 내일 살지"를 잘못 고르면 그날 매입액의 약 8% 를 더 낼 수 있다 — 내일 가격을 알면 줄일 수 있는 손실의 상한 |
| 급등이 시작되는 날의 상승폭 | kg당 평균 약 790원 (전날 대비 약 25%) | 급등을 하루 먼저 알고 전날 사 두면 kg당 이만큼 덜 낸다 |
| 급등 규모 | 60일 중앙값의 최대 7.3배 (2025.7–10) · 5.9배 (2024.8–10) · 5.0배 (2026.7–9) | 장마 · 폭염 철마다 몇 주씩 이어진다 — 2020년 버거 체인이 토마토를 뺀 상황과 같은 규모 |

급등 기준: 가격이 직전 60거래일 중앙값의 1.5배를 넘은 날. 20거래일 안에 다시 넘으면 같은 급등으로 묶었다.

매장 · 가맹 단위로 옮기면 (사용량은 **가정** — 실제 값으로 바꿔 넣는다)

- 급등 1회를 하루 먼저 알 때: 매장 하루 사용량 10kg(가정) × 790원 ≈ **매장당 7,900원**, 가맹점 100곳(가정)이면 **약 79만 원**
- 평상시: 매입액의 최대 8.4%/일 — 예측이 단순 예측(RMSE 612원/kg)보다 정확할수록 이 상한에 가까워진다
- 돈으로 바로 안 잡히는 손실: 품절 · "토마토 뺀 메뉴" 공지로 생기는 리뷰 · 브랜드 손상 — 보고서가 대체 메뉴 결정을 하루 앞당긴다

⚠️ 위 절감액은 예측이 맞았을 때의 값이다. 실제 효과는 토마토 LSTM 의 방향 적중률을 측정한 뒤 다시 계산한다.

수요 근거: 시세를 예측해 외식업체 구매 시점을 돕는 서비스(파라도)가 매출 9억 원(2024) → 약 32억 원(2025)으로 성장했다 (한경 2026.6.8). 이미 돈을 내고 쓰는 사람이 있는 문제다.

우리 차별점: 기존 서비스는 평소 정확도를 내세운다. 우리는 ① 폭염 · 장마 때 예측이 조용히 틀리는 순간을 잡아 스스로 재학습 · 재검증하고(AIOps), ② 그 상황을 점주가 읽을 수 있는 말로 바로 알려 준다(생성형 사이드카).

### 서비스가 잘못될 때 이해관계자가 겪는 일

| 상황 | 영향 |
|---|---|
| 장애 (서버 다운 · 모델 로드 실패) | 아침 구매 판단 전에 예측을 못 받아 전날처럼 감으로 산다 |
| 응답 지연 | 점주 앱 · 발주 화면이 기다리다 시간 초과 → 예측 없이 진행된다 |
| 품질 저하 (예측 오차 증가) | 에러 없이 틀린 값이 나간다. 과다 구매 → 폐기, 과소 구매 → 품절 · 토마토 뺀 메뉴. 아무도 눈치채지 못하는 것이 가장 위험하다 |
| 보고서 생성 실패 (LLM) | 보고서는 같은 숫자로 만든 정해진 양식으로 대신 나가고, 예측 API 는 계속 돈다 — 사이드카로 분리한 이유 |

→ 그래서 ②에 응답 · 가용성 · 품질 목표를 두고, ③에서 목표마다 지키는 장치를 둔다.

## ② AI 솔루션과 운영 목표

### 핵심 기능

- `POST /predict` — 최근 25거래일 (도매가격, 반입량)을 받아 다음날 도매가격(원/kg)을 돌려준다
- `POST /data/upload` — 가락시장 일별 시세 CSV 업로드(최소 40행) → 학습 · 드리프트 판정 데이터
- `GET /health` — 서버 상태와 모델 로드 여부
- `GET /report` (신규) — LLM 사이드카가 이력 로그 · aiops.log 를 읽어 만든 일일 보고서: 내일 가격 · 신뢰도 · 드리프트 · 재학습 이력
- `GET /metrics` (신규) — 이력 로그를 5분 단위로 집계한 응답 지연 · 에러율 · 경고
- 이력 로그 (신규) — 요청마다 JSONL 한 줄(입력 · 예측값 · 지연 · 모델 버전). 보고서와 ③ 지연 · 에러율 지표의 원천

모델의 역할: 예측은 LSTM 1개가 MLflow 레지스트리의 Production 버전으로 서빙된다. 게이트를 통과한 버전만 Production 이 된다. LLM 은 숫자를 만들지 않고, 예측 결과와 운영 이력을 사람이 읽는 문장으로 바꾸는 역할만 한다. 응답의 모델 버전(`production-v3` 등)으로 재학습 뒤 버전 전환이 그대로 보인다.

### 운영 목표

| 목표 | 값 | 근거 |
|---|---|---|
| 응답 시간 | /predict 첫 요청 포함 1초 이내 | 실측(입력 25일 · MLflow Production, 3회 평균): Lazy 첫 요청 5.27초(위반) · Eager 0.155초(충족), 이후 요청 0.022초 → 서버를 Eager 로 띄운다 (컨테이너 기본값) |
| 가용성 | 아침 구매 시간대 06–10시 99% | 이 시간에 못 받으면 ①의 장애 영향이 그대로 생긴다 |
| 품질 | 검증 RMSE ≤ 612원/kg (기본값 · 실험 후 확정) | 토마토 3년치 실측: 평균 3,727원/kg · "내일 가격 = 오늘 가격" 단순 예측 RMSE 612원/kg(평균의 16%). 하루 변동이 커서 HAIC 식 "가격의 2–4%"는 맞지 않는다 — 단순 예측보다 나아야 쓸 이유가 있다 |
| 드리프트 대응 | 감지 → 재학습 → 재검증 자동 | ①의 "아무도 모르는 품질 저하"를 사람 대신 시스템이 잡는다 |
| 보고서 | 매일 06:00 생성 (토마토 02:00 경매 기준) · LLM 실패가 예측 API 에 영향 없음 | 이력 로그 기반 LLM 요약 — 경락가가 확정된 뒤, 점주의 아침 구매 판단 전에 읽어야 한다. LLM 이 실패하면 같은 숫자로 정해진 양식 보고서를 낸다 |

## ③ 운영 설계

### 3-1. 배포 게이트

| 단계 | 기준 | 근거 · 실패 시 |
|---|---|---|
| 입력 스키마 검증 | 정확히 25거래일 · 가격 > 0 · 반입량 ≥ 0 | 어기면 422 로 거절 — 잘못된 입력이 모델까지 가지 않는다 (24 · 26일 · 가격 0 · 반입량 −1 모두 422 확인) |
| 업로드 검증 | Date · 가격 · 반입량 열 · 날짜 형식 · 순서 · 최소 40행 | 입력 25일 + 판정 윈도우 15건 = 40. 어기면 400 (39행 400 · 40행 200 확인) |
| 성능 임계값 | 검증 RMSE ≤ 612원/kg (기본값 · 실험 후 확정) 일 때만 Production 등록 | ② 품질 목표와 같은 값. 미달이면 배포 차단, 기존 Production 유지 |
| 성능 회귀 테스트 | 새 모델 RMSE ≤ 현재 Production RMSE | 임계값만 보면 기존보다 나쁜 모델도 통과한다. 구현 완료 — 10/1 실측에서 새 모델 1.73 > 현재 1.65 승격 차단 |

### 3-2. 모니터링 지표와 임계값

| 지표 | 임계값 | 근거 | 담당 |
|---|---|---|---|
| 응답 지연 | /predict P95 > 500ms (5분 집계, 이력 로그) | 평균은 느린 요청을 묻는다 (20건 중 2건이 1,000ms → 평균 118ms, P95 1,000ms). 실측 평소 20ms · Eager 첫 요청 150~200ms · Lazy 첫 요청 5,300ms → 정상에선 울리지 않고 1초 목표를 넘기 전에 경고 (교안 p.111 알림 설계 예시) | 서빙 |
| 에러율 | /predict 5xx > 1% (5분 집계, 이력 로그) | ② 가용성 06–10시 99% 의 오차 예산 1%. 요청이 적은 아침엔 사실상 "서버 오류 1건이면 경고" — 구매 시간대엔 1건도 알아야 한다. 잘못된 요청(422)은 세지 않는다 | 서빙 |
| 예측 오차 (모델 드리프트) | 최근 15거래일 RMSE > 612원/kg (기본값 · 실험 후 확정) | 15거래일 창은 지난 3년 급등 10건 중 6건을 탐지하고 평상시 오탐 3.5%였다 (3-6). 612원/kg 은 단순 예측의 RMSE 로, 운영 중에도 배포 게이트와 같은 기준을 적용한다 | 모니터링 · MLOps |
| 입력 분포 (데이터 드리프트) | 가격 또는 반입량 중 하나라도 PSI > 0.2 (기본값 · 실험 후 확정) | 최근 25거래일의 가격 · 반입량 분포를 학습 기준 기간과 각각 비교한다. PSI = Σ[(최근 비율 − 기준 비율) × ln(최근 비율 ÷ 기준 비율)]. 둘 중 하나라도 0.2 를 넘으면 데이터 드리프트 경고, 재학습은 RMSE 와 함께 판단한다 | 데이터 |
| LLM 보고서 (신규) | 생성 실패 · 30초 초과 · 드리프트 상태에서 "신뢰도 낮음" 문구 누락 | '신뢰도'는 확률값이 아니라 최근 RMSE 와 드리프트 상태에 따른 운영 상태다. 예측값 · 모델 버전 · 드리프트 상태는 코드가 제공하고, LLM 은 이를 문장으로만 바꾼다 | 모니터링 |

지연 · 에러율은 점주가 쓰는 `/predict` 만으로 계산한다. 드리프트 시뮬레이션(`/predict/batch-test`)은 요청 안에서 재학습(약 7.5초)이 돌아, 섞으면 데모 때마다 가짜 지연 경고가 난다.

### 3-3. 드리프트 대응 흐름

1. 감지 — 실제 가격이 들어올 때마다 예측과 비교해 최근 15건 RMSE 를 계산한다
2. 알림 — 임계값을 넘으면 aiops.log `[WARN] drift detected` → 점주 · 본사에 "가격 급변 감지 — 오늘 예측 신뢰도 낮음"
3. 재학습 — Production 가중치에서 이어서(warm start) 최근 25 + 25 거래일(한 달치 정답 + 입력)로 fine-tuning (학습률 1e-4 · 10 epoch)
4. 재검증 — 3-1 과 같은 게이트. 통과하면 새 버전을 Production 으로 승격하고 이전 버전은 Archived → `[OK]`
5. 실패 시 — 기존 Production 유지 + 실패 알림 → 사람이 확인. 문제 버전이 이미 나갔으면 MLflow 이전 버전으로 롤백
6. 보고 — 다음 보고서에 드리프트 · 재학습 · 버전 전환 이력을 문장으로 남긴다 (LLM 사이드카)

### 3-4. 실습에서 확인한 결함과 우리 대응

|---|---|---|
| 재학습 뒤 판정 윈도우 (가이드 p.17 #7) | 재학습 전 예측 오차가 윈도우에 남아 재학습 직후 또 드리프트로 판정될 수 있다 | 승격 시 판정 윈도우 초기화 (팀 결정) |

### 3-6. 시계열 길이 결정 근거 (입력 25 · 판정 윈도우 15 · 재학습 25)

스켈레톤 기본값(입력 20 · 윈도우 21)은 주식 관례다 — 주 5거래일 × 4주 = 20, 1년 252거래일 ÷ 12 = 21. 가락시장은 월~토 거래라 토마토 3년치 실측이 주 5.8거래일 · 한 달 25.3거래일이다. 그래서 토마토 데이터로 다시 정했다 (실측 10/1 · 2023.10–2026.09 · 908 거래일).

| 값 | 우리 | 근거 |
|---|---|---|
| 입력 길이 | 25거래일 | 가락시장 한 달. 입력을 늘리면 다음날 RMSE 가 522(5일) → 499(20일) → 494(25일) → 491(30일)원/kg 으로 줄다가 25 근처에서 둔해진다. 가격 변동률이 약 10거래일 뒤 되돌아오는 경향(자기상관 1일 +0.22 · 10일 −0.17)이 있어 10일보다 길게 본다 |
| 판정 윈도우 | 15거래일 (약 2.5주) | 지난 3년 급등 10건(60일 중앙값의 1.5배 초과) 기준 — 10일: 6건 · 오탐 4.7% / 15일: 6건 · 오탐 3.5% / 21일: 4건 · 오탐 3.3% / 25일: 4건 · 3.2%. 급등은 보통 7~19거래일 이어져 21일 창에서는 2.6~2.9배 급등 2건(2024.8 · 2025.7)이 묻힌다 |
| 재학습 범위 | 25 + 25 = 50행 | 윈도우와 분리 — 최근 한 달치 정답으로 fine-tuning. 15로 줄이면 학습 시퀀스가 너무 적다 |
| 업로드 최소 행 | 40 | 입력 25 + 윈도우 15 — 자동으로 따라온다 |

⚠️ 한계: LSTM 이 아니라 대체 모델(선형 회귀 · "내일 = 오늘" 오차)로 잰 값이다. 급등 정의와 임계값 612원/kg 은 분석용 기준이다. 팀 LSTM 학습 뒤 한 번 더 확인한다.

코드 반영 완료 — 입력 25 · 판정 윈도우 15 · 재학습 50행 · 업로드 최소 40행.
