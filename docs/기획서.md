# 농산품 시세 예보 AIOps — 기획서

한 줄 요약: 가락시장 토마토의 최근 25거래일 도매가격 · 반입량으로 다음날 도매가격(원/kg)을 예측하고, 폭염 · 장마 같은 기상 이변으로 예측이 틀리기 시작하면 감지 → 알림 → 자동 재학습 → 게이트 재검증을 사람 개입 없이 돌린다. 옆에 붙인 LLM 사이드카가 예측 이력과 운영 로그를 읽어 점주 · 본사가 바로 읽는 일일 보고서를 만든다 — 예측형 AI + 생성형 AI.

경매 시각과 보고서 시각

가락시장은 품목마다 경매 시각이 다르다. 그날 가격은 경매가 끝나야 확정되므로, 보고서는 **경매 시각 기준**으로 만든다. 토마토는 02:00 경매 → 경락가 확정 · 데이터 반영(3시간) → **05:00 보고서** → 점주 · 본사가 07시 전에 읽고 "오늘 더 살지, 하루 미룰지" 판단한다.

| 품목 분류 (가락시장 경매 시간표) | 경매 시각 | 보고서 시각 (경매 + 3시간) | 이번 구현 |
|---|---|---|---|
| 과일류 — **토마토** · 방울토마토 · 딸기 · 포도 · 참외 등 | 02:00 | **05:00** | **토마토** |
| 과일류 — 사과 · 배 · 수입과일 등 | 08:00 | 11:00 | 설계 |
| 채소류 — 상추 · 시금치 등 규격 출하품 | 18:30 | 21:30 | 설계 |
| 채소류 — 배추 · 양파 | 23:00 | 다음날 02:00 | 설계 |

→ 품목을 늘리면 품목별 경매 시각으로 보고서 시각이 정해진다 (설정값 `auction_time`). 지금 그룹(사계절용 · 계절용) 품목은 모두 과일류 02:00 경매라 같은 05:00 보고서를 쓴다.

## ① 이해관계자 가치 (Pain Point)

주 사용자: 외식 프랜차이즈 — 실습가이드 예시 "프랜차이즈 수요 예측"(점주 · 본사 SCM · 경영진)과 같은 구조다.


| 이해관계자 | 지금 겪는 불편 (근거) | 우리가 주는 가치 |
|---|---|---|
| 가맹점주 (주 사용자) | 본사가 채소는 점주가 직접 사게 해서 가격 변동을 점주가 떠안는다. 토마토를 적게 넣으면 배달앱 리뷰로 불만이 바로 돌아온다 (아시아타임즈 2024.9) | 매일 아침 "오늘 더 살지, 하루 미룰지" 판단에 쓰는 내일 가격 + 읽기 쉬운 일일 보고서 |
| 본사 구매 · SCM | 연간 계약을 해도 수급 비상 때는 물량이 모자란다. 2020년 장마 · 태풍으로 도매가가 2배를 넘자 롯데리아 · 버거킹이 토마토를 뺐다 (이투데이 2020.9). 2025년에는 계약 단가를 약 30% 올렸다 (아시아경제 2025.4) | 급등 조짐을 먼저 보고 보충 구매 또는 "토마토 제외" 공지를 미리 결정 |
| 경영진 · 메뉴팀 | 토마토를 줄이거나 빼면서 품질 · 브랜드가 손상된다 (아시아경제 2025.4) | 대체 메뉴 결정을 하루라도 앞당김 |
| 확장: 농협 · 산지 / 정부 | 출하 시점을 정해야 하는 산지, 수급 안정 정책을 펴야 하는 정부도 같은 "내일 가격"이 필요하다 (교수님 피드백) | 같은 API · 보고서를 출하 · 수급 판단용으로 — 발표에서 확장 방향으로 제시 |

수요 근거: 시세를 예측해 외식업체 구매 시점을 돕는 서비스(파라도)가 매출 9억 원(2024) → 약 32억 원(2025)으로 성장했다 (한경 2026.6.8). 이미 돈을 내고 쓰는 사람이 있는 문제다.

우리 차별점: 기존 서비스는 평소 정확도를 내세운다. 우리는 ① 폭염 · 장마 때 예측이 조용히 틀리는 순간을 잡아 스스로 재학습 · 재검증하고(AIOps), ② 그 상황을 점주가 읽을 수 있는 말로 바로 알려 준다(생성형 사이드카).

서비스가 잘못될 때 이해관계자가 겪는 일


| 상황 | 영향 |
|---|---|
| 장애 (서버 다운 · 모델 로드 실패) | 아침 구매 판단 전에 예측을 못 받아 전날처럼 감으로 산다 |
| 응답 지연 | 점주 앱 · 발주 화면이 기다리다 시간 초과 → 예측 없이 진행된다 |
| 품질 저하 (예측 오차 증가) | 에러 없이 틀린 값이 나간다. 과다 구매 → 폐기, 과소 구매 → 품절 · 토마토 뺀 메뉴. 아무도 눈치채지 못하는 것이 가장 위험하다 |
| 보고서 생성 실패 (LLM) | 보고서만 빠지고 예측 API 는 계속 돈다 — 사이드카로 분리한 이유 |

→ 그래서 ②에 응답 · 가용성 · 품질 목표를 두고, ③에서 목표마다 지키는 장치를 둔다.


## ② AI 솔루션과 운영 목표

핵심 기능

POST /predict — 최근 25거래일 (도매가격, 반입량)을 받아 다음날 도매가격(원/kg)을 돌려준다

POST /data/upload — 가락시장 일별 시세 CSV 업로드(최소 40행) → 학습 · 드리프트 판정 데이터

GET /health — 서버 상태와 모델 로드 여부

GET /report (신규) — LLM 사이드카가 이력 로그 · aiops.log 를 읽어 만든 일일 보고서: 내일 가격 · 신뢰도 · 드리프트 · 재학습 이력

이력 로그 (신규) — 요청마다 JSONL 한 줄(입력 · 예측값 · 지연 · 모델 버전). 보고서와 ③ 지연 · 에러율 지표의 원천

모델의 역할: 예측은 LSTM 1개가 MLflow 레지스트리의 Production 버전으로 서빙된다. 게이트를 통과한 버전만 Production 이 된다. LLM 은 숫자를 만들지 않고, 예측 결과와 운영 이력을 사람이 읽는 문장으로 바꾸는 역할만 한다.

운영 목표


| 목표 | 값 | 근거 |
|---|---|---|
| 응답 시간 | /predict 첫 요청 포함 1초 이내 | 실습 실측: Lazy 첫 요청 5.555초(위반) · Eager 0.236초(충족) → 서버를 Eager 로 띄운다 (컨테이너 기본값) |
| 가용성 | 아침 구매 시간대 06–10시 99% | 이 시간에 못 받으면 ①의 장애 영향이 그대로 생긴다 |
| 품질 | 검증 RMSE ≤ 단순 예측 RMSE 612원/kg 미만 | 토마토 3년치 실측: 평균 3,727원/kg · "내일 가격 = 오늘 가격" RMSE 612원/kg(평균의 16%). 하루 변동이 커서 HAIC 식 "가격의 2–4%"는 맞지 않는다 — 단순 예측보다 나아야 쓸 이유가 있다 |
| 드리프트 대응 | 감지 → 재학습 → 재검증 자동 | ①의 "아무도 모르는 품질 저하"를 사람 대신 시스템이 잡는다 |
| 보고서 | 매일 05:00 생성 (토마토 02:00 경매 기준) · 07시 전 읽음 · LLM 실패가 예측 API 에 영향 없음 | 경락가가 확정된 뒤 · 점주의 아침 구매 판단 전에 읽어야 한다 · 사이드카 분리 · LLM 실패 시 템플릿 보고서 |


## ③ 운영 설계


### 3-1. 배포 게이트


| 단계 | 기준 | 근거 · 실패 시 |
|---|---|---|
| 입력 스키마 검증 | 정확히 25거래일 · 가격 > 0 · 반입량 ≥ 0 | 어기면 422 로 거절 — 잘못된 입력이 모델까지 가지 않는다 (실습에서 422 확인) |
| 업로드 검증 | Date · 가격 · 반입량 열 · 최소 40행 | 입력 25일 + 판정 윈도우 15건 = 40. 어기면 400 |
| 성능 임계값 | 검증 RMSE ≤ 임계값 원/kg 일 때만 Production 등록 | ② 품질 목표와 같은 값. 미달이면 배포 차단, 기존 Production 유지 |
| 성능 회귀 테스트 | 새 모델 RMSE ≤ 현재 Production RMSE | 임계값만 보면 기존보다 나쁜 모델도 통과한다. 구현 범위 팀 결정 |


### 3-2. 모니터링 지표와 임계값


| 지표 | 임계값 | 근거 | 담당 |
|---|---|---|---|
| 응답 지연 | 평균 > 500ms (5분 집계, 이력 로그) | ② 1초 목표의 절반에서 미리 경고 (교안 p.111 알림 설계 예시) | 서빙 |
| 에러율 | > 5% (5분 집계, 이력 로그) | 가용성 목표를 지키기 위한 조기 신호 (교안 p.111) | 서빙 |
| 예측 오차 (모델 드리프트) | 최근 15거래일 RMSE > 임계값 원/kg | 15거래일(약 2.5주) — 지난 3년 급등 10건 중 6건을 잡고 평상시 오탐 3.5% (21일은 4건 · 3.3%) — 3-6 참고. 게이트와 같은 값이라 배포 때 기준을 운영 중에도 지킨다 | 모니터링 · MLOps |
| 입력 분포 (데이터 드리프트) | 가격 · 반입량 PSI > 0.2 | 오차가 커지기 전에 입력이 달라진 것을 먼저 본다. 구현 범위 팀 결정 | 데이터 |
| LLM 보고서 (신규) | 생성 실패 · 30초 초과 · 드리프트 상태인데 "신뢰도 낮음" 누락 | 생성형 출력도 에러 없이 틀릴 수 있다 — 예측 모델과 같은 방식으로 감시 | 모니터링 |


### 3-3. 드리프트 대응 흐름

감지 — 실제 가격이 들어올 때마다 예측과 비교해 최근 15건 RMSE 를 계산한다

알림 — 임계값을 넘으면 aiops.log [WARN] drift detected → 점주 · 본사에 "가격 급변 감지 — 오늘 예측 신뢰도 낮음"

재학습 — Production 가중치에서 이어서(warm start) 최근 25 + 25 거래일(한 달치 정답 + 입력)로 fine-tuning (학습률 1e-4 · 10 epoch)

재검증 — 3-1 과 같은 게이트. 통과하면 새 버전을 Production 으로 승격 → [OK]

실패 시 — 기존 Production 유지 + 실패 알림 → 사람이 확인. 문제 버전이 이미 나갔으면 MLflow 이전 버전으로 롤백

보고 — 다음 보고서에 드리프트 · 재학습 · 버전 전환 이력을 문장으로 남긴다 (LLM 사이드카)


### 3-4. 실습에서 확인한 결함과 우리 대응


| 결함 | 실습에서 본 것 | 우리 대응 |
|---|---|---|

| 재학습 뒤 판정 윈도우 (#7) | 재학습 전 예측 오차가 윈도우에 남아 재학습 직후 또 드리프트로 판정될 수 있다 | 승격 시 판정 윈도우 초기화 팀 결정 |

### 3-6. 시계열 길이 결정 근거 (입력 25 · 판정 윈도우 15 · 재학습 25)

스켈레톤 기본값(입력 20 · 윈도우 21)은 주식 관례다 — 주 5거래일 × 4주 = 20, 1년 252거래일 ÷ 12 = 21. 가락시장은 월~토 거래라 토마토 3년치 실측이 주 5.8거래일 · 한 달 25.3거래일이다. 그래서 토마토 데이터로 다시 정했다 (실측 10/1 · 2023.10–2026.09 · 908 거래일).

| 값 | 스켈레톤 | 우리 | 근거 |
|---|---|---|---|
| 입력 길이 | 20 | 25거래일 | 가락시장 한 달. 입력을 늘리면 다음날 RMSE 가 522(5일) → 499(20일) → 494(25일) → 491(30일)원/kg 으로 줄다가 25 근처에서 둔해진다. 가격 변동률이 약 10거래일 뒤 되돌아오는 경향(자기상관 1일 +0.22 · 10일 −0.17)이 있어 10일보다 길게 본다 |
| 판정 윈도우 | 21 | 15거래일 (약 2.5주) | 지난 3년 급등 10건(60일 중앙값의 1.5배 초과) 기준 — 10일: 6건 · 오탐 4.7% / 15일: 6건 · 오탐 3.5% / 21일: 4건 · 오탐 3.3% / 25일: 4건 · 3.2%. 급등은 보통 7~19거래일 이어져 21일 창에서는 2.6~2.9배 급등 2건(2024.8 · 2025.7)이 묻힌다 |
| 재학습 범위 | 21 + 20 = 41행 | 25 + 25 = 50행 | 윈도우와 분리 — 최근 한 달치 정답으로 fine-tuning. 15로 줄이면 학습 시퀀스가 너무 적다 |
| 업로드 최소 행 | 41 | 40 | 입력 25 + 윈도우 15 — 자동으로 따라온다 |

⚠️ 한계: LSTM 이 아니라 대체 모델(선형 회귀 · "내일 = 오늘" 오차)로 잰 값이다. 급등 정의와 임계값 612원/kg 은 분석용 기준이다. 팀 LSTM 학습 뒤 한 번 더 확인한다.
